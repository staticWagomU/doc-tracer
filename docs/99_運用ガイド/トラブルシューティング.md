# トラブルシューティングガイド

doc-tracerの運用でハマりやすいポイントと解決策。

---

## 1. スキャンで0件になる

### 症状

```
スキャン完了: ドキュメント 0件, コード要素 0件
```

### 原因

`docs/` ディレクトリが存在しない、または空。

### 解決策

```bash
# ディレクトリ構造を確認
ls -la docs/

# 5層構造で作成
mkdir -p docs/{01_要件定義,02_仕様書,03_基本設計,04_詳細設計,05_プログラム設計}
```

### 予防策

- doc-tracerを導入する際は、**必ず先に`docs/`ディレクトリと最低1つのMarkdownファイルを作成**してからスキャンする
- スキャン結果が0件の場合は、パスとディレクトリ構造を確認

---

## 2. リンク切れが大量に発生する

### 症状

```
⚠️  リンク切れ (10件):
  - doc:xxx -> module:yyy (uses)
```

### 原因

ドキュメントの `uses:` フィールドで参照しているノードがまだ存在しない。

**典型的なパターン**:
- ドキュメントを先に書いて `uses: module:scan` と書いたが、コードのスキャンがまだ
- コードファイルのパーサーが未実装（Go、Python等）

### 解決策

1. **参照先が存在するか確認**
   ```bash
   ./doc-tracer check
   ```

2. **コードが先、ドキュメントの参照は後**
   - まずコードをスキャンして、どんなノードIDが生成されるか確認
   - その後で `uses:` フィールドに正しいIDを記載

3. **存在しないノードへの参照は書かない**
   - 実装予定のコードへの参照を書きたい場合は、コメントで残す
   - YAMLフロントマターには実在するノードIDのみ記載

### 予防策

```bash
# スキャン後にすぐチェックを実行する習慣
./doc-tracer scan . && ./doc-tracer check
```

## 3. コードがドキュメントに紐づかない

### 症状

ビューワーでグラフを見ると、コードノード（緑色）がドキュメントノード（青緑色）と分離している。

### 原因

1. **パーサーが未実装**: その言語のパーサーがscan.goに存在しない
2. **`uses:`フィールドの未記載**: プログラム設計書に対応コードへの参照がない
3. **ノードIDの不一致**: ドキュメントに書いたIDと、スキャンで生成されるIDが異なる

### 解決策

**Step 1: スキャン結果を確認**

```bash
# どんなノードIDが生成されているか確認
curl -s http://localhost:8888/api/graph | jq '.nodes[] | select(.type == "module") | .id'
```

**Step 2: プログラム設計書に`uses:`を追加**

```yaml
---
trace:
  id: doc:docs/05_プログラム設計/scanコマンド設計書.md
  parent:
    - doc:docs/04_詳細設計/スキャン処理詳細設計書.md
  uses:
    - module:scan  # ← ここにスキャン結果のノードIDを記載
---
```

**Step 3: 再スキャンして確認**

```bash
./doc-tracer scan . && ./doc-tracer check
```

### 予防策

- 05_プログラム設計書を書く際は、**必ず対応するコードファイルへの`uses:`参照を含める**
- 新しい言語のコードを追加した場合は、**パーサーの実装が必要**

---

## 4. 特定のコードが独立ノードになる

### 症状

ビューワーでグラフを見ると、一部のコードノードが孤立している。

### 原因

そのコードを参照するドキュメントが存在しない。

**よくある例**:
- `main.go` (エントリポイント)
- `root.go` (CLIルートコマンド)
- `internal/db/schema.go` (共通モジュール)

### 解決策

適切な設計書に `uses:` 参照を追加する。

| 独立コード | 紐付け先ドキュメント |
|-----------|---------------------|
| `module:main` | アーキテクチャ設計書 |
| `module:root` | アーキテクチャ設計書 or CLI設計書 |
| `module:db/schema` | データモデル設計書 |

```yaml
# docs/03_基本設計/アーキテクチャ設計書.md
---
trace:
  id: doc:docs/03_基本設計/アーキテクチャ設計書.md
  parent:
    - doc:docs/02_仕様書/機能仕様書.md
  uses:
    - module:main
    - module:root
---
```

### 予防策

- **全コードが何らかのドキュメントから参照されている状態を維持**
- 共通モジュールは基本設計書レベルで参照
- 個別機能は05_プログラム設計書で参照

## 5. ポートが既に使用中

### 症状

```
listen tcp :8888: bind: address already in use
```

### 解決策

```bash
# 使用中のプロセスを確認
lsof -i :8888

# 別ポートで起動
./doc-tracer serve --port 8889
```

---

## 6. チェックリスト：ドキュメント作成完了条件

ドキュメント作成作業が「完了」したと言える条件:

- [ ] `./doc-tracer scan .` でドキュメント件数 > 0
- [ ] `./doc-tracer scan .` でコード要素件数 > 0（コードがある場合）
- [ ] `./doc-tracer check` で「問題なし」
- [ ] `./doc-tracer serve` でビューワー起動
- [ ] ビューワーで全ノードが接続されていることを目視確認
- [ ] 孤立ノードがないことを確認

```bash
# 一括確認コマンド
./doc-tracer scan . && ./doc-tracer check && echo "✅ 完了"
```
