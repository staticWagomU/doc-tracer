# doc-tracer ドキュメント作成ルール

doc-tracerを使ってドキュメントを作成・管理する際の必須ルール。

---

## 絶対に守ること

### 1. 作業順序を厳守

**コードが先、ドキュメントの参照は後**

```
❌ 間違い: ドキュメントを書く → uses: module:xxx を書く → スキャン → リンク切れ
✅ 正解:   スキャン → ノードID確認 → ドキュメントに正しいIDを書く → 再スキャン
```

### 2. スキャン後は必ずチェック

```bash
# この2つはセットで実行
./doc-tracer scan . && ./doc-tracer check
```

チェックで問題が出たら、**問題を解決してから次の作業に進む**。

### 3. ビューワーで目視確認

コマンドラインの「問題なし」だけでは不十分。**必ずビューワーでグラフを確認**する。

```bash
./doc-tracer serve --port 8888
# ブラウザで http://localhost:8888 を開く
```

確認ポイント:
- 全ノードが接続されているか（孤立ノードがないか）
- ドキュメント→コードの線が見えるか
- 5層構造が正しく表現されているか

---

## ドキュメント作成手順

### Step 1: ディレクトリ構造を先に作る

```bash
mkdir -p docs/{01_要件定義,02_仕様書,03_基本設計,04_詳細設計,05_プログラム設計}
```

### Step 2: 上位層から順に作成

```
01_要件定義 → 02_仕様書 → 03_基本設計 → 04_詳細設計 → 05_プログラム設計
```

**理由**: 下位層は上位層を `parent:` で参照するため、上位が存在しないとリンク切れになる。

### Step 3: YAMLフロントマターのテンプレート

```yaml
---
trace:
  id: doc:docs/XX_レイヤー名/ファイル名.md
  parent:
    - doc:docs/上位レイヤー/親ドキュメント.md
---
```

**注意**: `id` はファイルパスと完全に一致させる。

### Step 4: コードとの紐付け（05_プログラム設計のみ）

```yaml
---
trace:
  id: doc:docs/05_プログラム設計/xxxコマンド設計書.md
  parent:
    - doc:docs/04_詳細設計/xxx詳細設計書.md
  uses:
    - module:xxx  # ← スキャン結果で確認したノードID
---
```

### Step 5: 完了確認

```bash
./doc-tracer scan . && ./doc-tracer check && ./doc-tracer serve --port 8888
```

ビューワーで全ノードが接続されていることを確認して完了。

## よくあるミスと対策

| ミス | 症状 | 対策 |
|------|------|------|
| `docs/` がない | スキャン0件 | 先にディレクトリ作成 |
| 存在しないノードを参照 | リンク切れ | スキャンでノードID確認してから書く |
| `uses:` の未記載 | コード孤立 | 05_プログラム設計に必ず `uses:` を書く |
| 共通モジュールの参照漏れ | 一部コード孤立 | main, root, db等は03_基本設計で参照 |
| チェックせずに進む | 問題の蓄積 | スキャン後は必ずチェック |

## 完了条件チェックリスト

- [ ] `docs/` ディレクトリに5層構造がある
- [ ] `./doc-tracer scan .` でドキュメント件数 > 0
- [ ] `./doc-tracer scan .` でコード要素件数 > 0
- [ ] `./doc-tracer check` で「問題なし」
- [ ] ビューワーで全ノードが接続されている
- [ ] 孤立ノードがない

**全て満たすまでドキュメント作成は「完了」ではない。**
